# Editing this role-study application

This is a new, independently scoped application. Do not modify any neighboring application or wider career repository. Read README.md before editing.

Direct user instructions on September 27, 2026 superseded the initial role-only prompt: include selected personal career material and publish so anyone with the link can access it without sign-in. This does not authorize lifting specific workspace disclosure holds, uploading original private documents, or adding other people's personal information. The public career records preserve user-statement versus issuer-record-copy classification.

## Content workflow

Claude/Astra may propose or edit `content/`, `schema/`, and `content/gaps/` within the current user-authorized task. Preserve source captures, IDs, classifications, dates, locators, and source boundaries. New candidate facts require the governing workspace's specific evidence and disclosure review. Scope statements and practice prompts must not be silently upgraded into achieved-results claims.

Never invent employer policy, an org chart, an interview format, or official interview questions. Never promote inference or a drill to posting/employer_public without a new source and visible diff. Never attribute a vendor's customer-story metrics to the candidate or this specific job. A tools list establishes neither proficiency nor current subscription/connector access.

Candidate statements and document copies must retain their evidence class, period, population, attribution limits, and lifecycle. Operating BEAT remains a personal concept never actualized or piloted. Do not add held operational totals, private contracts, original source files, recordings, local paths, or a private ledger. Public personal facts belong in `content/career/cards.json`, not in posting records.

Do not edit `app/data/content.json`, `content.sha256`, or generated `docs/` manually. Rebuild, validate, run rejection tests, and test the UI over HTTP. Do not weaken validation to make a content defect pass. A source change requires regenerated data; publication requires another complete check and export.

## Gap report shape

Every gap names:

- path
- missing class or source
- unmapped posting sentence, or “not a posting-coverage gap”
- proposed patch and evidence needed

An unknown is an acceptable research state. Do not manufacture an answer to close a gap. Keep the source version and changed assumption visible.

## Claude review boundary

Claude's GitHub Project integration reads file names and contents on one selected branch. It does not review PRs, issues, or the live Pages DOM through that integration. Ask it to inspect the source files, not “open the app.” Refresh the synced content after each merge. A source review cannot replace browser acceptance.

## Scope of code changes

Renderer changes require explicit implementation scope, which the current build request supplies. Keep study prose in `content/`; the JavaScript is a renderer and interaction layer. No paid APIs, accounts, analytics, third-party fonts, or automatic upload of practice responses are part of this edition. Do not add them without a later scoped user request.
